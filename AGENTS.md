# EFIRIO Atmos — правила для AI-агентов и разработчиков

## Статус и область работ
Проект находится на стадии архитектуры. Не начинать реализацию, развёртывание, подключение платных API, регистрацию сервисов или публикацию релизов без отдельного задания. Прежде чем менять код, читать README.md и документы docs/.

## Неизменяемые требования
- Приложение бесплатное, некоммерческое, свободно распространяемое. Собственный код — MIT; MIT допускает коммерческое использование третьими лицами.
- Нет аккаунтов, рекламы, трекеров, пользовательской аналитики и платёжных функций.
- Сервер не хранит персональные настройки, избранные координаты, профили аллергии или историю перемещений.
- Пользовательские настройки — локально на устройстве. Нет синхронизации, импорта/экспорта или переноса профиля.
- Геолокация только после явного действия пользователя и разрешения браузера. Ручной выбор точки и поиск должны работать без геолокации.
- Не передавать точные координаты серверу без необходимости; предпочитать региональные пакеты. Не обещать абсолютную анонимность: IP и сетевые метаданные существуют.
- Приоритет — ближайшие доступные, свежие и достоверные метеонаблюдения. Сбор разрешённой телеметрии из максимально широкого набора независимых источников.
- Для каждого значения различать: ИЗМЕРЕНО / ОЦЕНЕНО / NOWCAST / ПРОГНОЗ. Показывать источник, время измерения, актуальность, качество и неопределённость.
- Не усреднять без проверки: учитывать дубли, неисправные датчики, высоту, расстояние, рельеф, условия размещения и независимость источников.
- Отсутствующие данные обозначать явно. Не выдумывать станции, API, измерения, прогнозы, лицензии или точность.
- Карта: OpenStreetMap + MapLibre GL JS; OpenFreeMap лишь кандидат на тайлы. Начальный радиус поиска станций 1 км, далее адаптивное расширение. Это не ограничение точности координат.
- Цветовая палитра EFIRIO — из утверждённых фирменных материалов; не придумывать HEX.

## Безопасность
- Публичный API только для чтения, отдельные минимально привилегированные сборщики; никакой записи пользовательского контента.
- Секреты не коммитить и не отдавать в браузер. Ограничения запросов, проверка входных данных, безопасные зависимости, защита целостности, контроль нагрузки.
- Минимизировать логи, исключать координаты и чувствительные параметры из URL/логов по возможности; учитывать журналы прокси, CDN и сторонних провайдеров.
- Не считать публичные Mesh/MQTT-пакеты автоматически разрешёнными для массового сбора. Соблюдать правила сетей, лицензии и права владельцев датчиков.
- Запрещены скрытые внешние запросы, телеметрия приложения и фоновые операции, не требуемые задачей.

## Дисциплина разработки
- Работать небольшими проверяемыми изменениями; не проводить длительные тестовые матрицы без необходимости.
- Запускать только минимально необходимые тесты для изменённых компонентов; сообщать о зависании, ожидании сети, тайм-ауте и блокировке, а не молча ждать.
- Не выполнять git push, merge, публикацию, развёртывание или опасные операции без явного разрешения в задаче.
- Не менять требования или лицензии по собственному усмотрению.
- Промпты и отчёты для владельца по умолчанию на русском; публичная документация может быть на английском.
- После каждого задания: кратко сообщить изменения, тесты, ограничения и незавершённые пункты.

## Локализация UI — обязательное требование
- Два языка интерфейса с первого релиза: русский (ru) и английский (en).
- При первом запуске обязательно показать явный выбор «Русский / English», не определять окончательный выбор автоматически по языку браузера.
- Сохранять выбор только локально, использовать при следующих запусках; язык можно сменить в настройках без перезапуска.
- Язык UI не влияет на единицы измерения, координаты, источники и точность данных.
- Экран первого запуска не требует аккаунта, геолокации или передачи пользовательских настроек серверу.
- Все строки интерфейса, ошибки, статусы и предупреждения вынести в отдельные словари переводов ru/en; не вшивать строки в компоненты.
